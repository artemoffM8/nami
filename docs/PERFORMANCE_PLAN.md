# NAMI — Engineering Measurements, Phase 1

This phase introduces **reproducible measurements**, not claims of iOS performance.

## Existing architecture: audit findings

- The app project is generated by `Tools/generate_xcodeproj.py`.
- `Tools/verify_project.py` performs static/project-integrity checks without Xcode.
- The current Ubuntu CI runs this verifier and imports the Python reference solver. It **does not** build the iOS app or run Swift/XCUITest tests.
- `Packages/NamiDomain` is Foundation-only and is a suitable target for future isolated algorithm benchmarks.
- `PROJECT_STATUS.md` reports an earlier snapshot (158 tests / 2,903 verifier checks), whereas the current README reports 176 / 2,913. These are dated claims, not live results.

## Implemented now

`python3 Tools/measure_verifier.py --output /tmp/nami-verifier.json`

The script runs the existing verifier in a subprocess, captures elapsed wall-clock milliseconds, Python version, platform, timestamp, and exit code. It returns a nonzero exit code if verification fails or times out. No benchmark data is committed; run output is environment-dependent.

**Success criteria:** CI executes the wrapper successfully, emits parseable JSON with `schema_version=1`, nonnegative `duration_ms`, and `exit_code=0`. No fixed performance threshold is imposed across different runners.

## Next performance phase (macOS required)

1. Add isolated solver fixtures (easy/medium/hard catalog IDs, deterministic inputs).
2. Benchmark 30 warm iterations per fixture on a pinned device/simulator and Xcode version; report median, p95, variance, and environment.
3. Profile launch time, peak memory, and UI responsiveness with Instruments.
4. Add XCUITest for launch, hint, undo, persistence, VoiceOver, and Dynamic Type.
5. Compare against a checked-in baseline only on equivalent hardware and software, with an explicitly chosen regression budget.

**Do not claim:** FPS, energy efficiency, launch latency, or solver throughput before those measurements exist.
